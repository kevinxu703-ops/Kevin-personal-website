- 需要上传的英文 Markdown 放在 公理：数学史与哲学/英文版本/。未审英文工作稿放在其 _drafts/ 子目录。
- 外部图片先追溯来源及使用许可。可复用时下载成网站本地资源并记录来源；若无法取得或授权不清，向用户索取或讨论替代方案。

## 页面架构

1. 首页 Writing & Reading 放一张系列精选卡，链接到系列目录。
2. writing/index.html 将本系列列为主要写作项目，普通文章与读书笔记仍独立存在。
3. 系列目录位于 writing/axioms/index.html，公开名称为 Axioms，副标题为 Essays on the History and Philosophy of Mathematics。仅已发表篇目给文章链接，未来篇目暂不承诺标题和顺序。
4. 单篇文章只用稳定编号网址，例如 writing/axioms/1-1.html。英文标题可修改而无需更改网址。导言可用 writing/axioms/0.html。页面含所属卷、日期、返回目录、上一篇/下一篇、注释和参考资料。
5. thinking/index.html 仅放交叉链接，保留其独立内容方向。

## 本站生成方式

- 正式英文 Markdown 是内容源：公理：数学史与哲学/英文版本/00-introduction.md 和 1-1.md。
- 使用 tools/axioms-build/build.mjs 生成 writing/axioms/0.html 和 1-1.html。依赖在 tools/axioms-build/package.json 与 pnpm-lock.yaml 中，先在该目录安装依赖，然后从网站根目录运行 node tools/axioms-build/build.mjs。
- 生成器同时把 KaTeX 的样式和字体复制到 assets/vendor/katex，保证数学公式不依赖外部 CDN。生成的 HTML 和数学静态资源均须提交；依赖目录 node_modules 不提交。
- 文章标题可在 Markdown 中修改而不改变编号网址。新增文章时在生成器的 articles 清单、系列目录与前后篇导航中登记。首页/列表页只显示已准备公开的内容。

## 阅读器式布局

- 桌面端左侧为可独立滚动的目录，右侧为较窄的阅读栏。目录至少两级：文章/主要章节和其下的小节。
- 单篇目录从英文稿的二级、三级标题自动生成；系列总目录由一份明确的篇目清单生成或维护，不在多个页面重复手工抄写。
- 点击一级条目可平滑展开或收起二级条目；点击章节跳到锚点。目录随阅读位置高亮，URL 保留可分享的章节定位。
- 交互支持键盘、明确的焦点状态、ARIA 展开状态和系统的减少动态效果设置。动画保持轻而短，不影响快速浏览。
- 手机端把目录收纳为可打开的章节面板，仍保留两级结构，不让侧栏挤压正文。
- 公式、长公式、脚注、引文、图片和图注均需在手机上检查。解释图应服务论证，不逐节堆装饰。
- 2.4 等长文先用导读、页内目录和锚点解决导航问题；是否拆成多页要依据内容结构并经用户确认。

## 翻译与编辑

1. 先核对最新中文源稿、V3 大纲和该篇的公开状态，记录中英文对应关系。
2. 以“导言 + 1.1”为样章，确定英文标题、分卷名称、术语表、注释方式和读者难度，再分批推进。
3. 保留原稿的论证、直观例子和数学深度。英语可调整句式与衔接，但不可擅改核心主张。长文导读或摘要须区分于原文观点。
4. 逐项核对定义、公式、证明依赖、史实、人物及文献。来源不足或有争议的内容标为待核实，不编造引文。
5. 维护术语表，特别留意 set/class、axiom/scheme、consistency/completeness、truth/provability、forcing、constructivism。
6. 公众号原文只在已公开且用户希望关联时链接。第三方图片和引文需单独核查版权与出处。

## 每次更新的操作顺序

1. 用户指定新增或修订内容后，比较中文目录、英文版本、网站页面和本笔记记录。
2. 确认内容所属卷、前后衔接、是否获准公开，以及旧页面是否受影响。
3. 翻译、编辑并核查数学与史实；把存疑点及重要改动交给用户审阅。样章与实质性删改须先确认。若用户在本次请求中已明确授权某批内容上线，常规翻译和排版无需逐项重复确认。
4. 内容达到本次委托的发布条件后，正式英文 Markdown 进入 英文版本/，同步制作或更新网站页面、目录和必要图片。
5. 本地检查公式、链接、两级目录、键盘、手机布局和资源；精确暂存获准文件并审阅提交差异。
6. 推送 GitHub，确认 Vercel 的线上页面与资源已更新；记录源文件、英文稿、发布时间和未解决事项。
