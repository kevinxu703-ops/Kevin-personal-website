Article 2.3 · At the Limits of Axioms

Turing and the Limits of Computation

Finite rules, unbounded runs, and numbers no algorithm can list

Checking a supplied proof and finding a proof are different tasks. A proof is a finite object. A search through all possible proofs has no predetermined stopping point.

If a sentence is provable in an effectively specified theory, systematic enumeration will eventually find a proof. If it is unprovable, the search may continue forever. At any finite stage, failure to find a proof could mean that none exists, or simply that we have not searched far enough.

To establish a limit on every possible search procedure, we first need to say what a procedure is.

The decision problem

Hilbert and Ackermann's Entscheidungsproblem asked for a method that always terminates and decides whether an arbitrary first-order formula is logically valid.

For a sentence φ\varphiφ, the two possible outcomes are

⊨φor⊭φ.\models\varphi \qquad\text{or}\qquad \not\models\varphi.⊨φor⊨φ.

Validity means truth in every structure of the appropriate language. For finitely many axioms A1,…,AnA_1,\ldots,A_nA1​,…,An​, logical consequence can be tested by asking whether

(A1∧⋯∧An)⟶ψ(A_1\land\cdots\land A_n)\longrightarrow\psi(A1​∧⋯∧An​)⟶ψ

is valid.

Gödel's completeness theorem connects validity to formal proof. Enumerating logical proofs therefore finds every valid formula eventually. It offers no guarantee of stopping on an invalid formula.

The desired decision procedure had to settle both cases.

Several accounts of effective calculation

In the 1930s, Church used lambda definability, Kleene studied recursive functions, and Post described finite symbolic processes. Turing approached the problem by analyzing the work of a human calculator following explicit rules.

The models were developed through different constructions, yet captured the same computable functions. Their equivalence provided important evidence for the Church–Turing thesis: every effective mechanical calculation can be performed by a Turing machine.

The thesis connects a mathematical model with an informal idea of effective calculation. Equivalence among the formal models is a theorem. The identification with every possible effective method has a different status.

What a calculator can inspect

At a particular moment, a calculator can attend to only finitely much information. A long calculation may require more paper, but each step reads or changes a limited number of marks.

Turing abstracted this activity into a tape divided into squares, a head that reads and writes symbols, and a finite set of control states. The next action depends on the current state and the symbol under the head.

An unbounded tape removes an accidental resource limit. The machine visits only finitely many squares in any finite run. It never uses an actually completed infinite calculation.

A modern machine model

Write a deterministic machine as

M=(Q,Γ,Σ,δ,q0,qh,B).M=(Q,\Gamma,\Sigma,\delta,q_0,q_h,B).M=(Q,Γ,Σ,δ,q0​,qh​,B).

Here QQQ is a finite state set, Γ\GammaΓ a finite tape alphabet, Σ\SigmaΣ the input alphabet, BBB the blank symbol, and q0,qhq_0,q_hq0​,qh​ the initial and halting states. A transition

δ(q,a)=(q′,b,D),D∈{L,R},\delta(q,a)=(q',b,D),\qquad D\in\{L,R\},δ(q,a)=(q′,b,D),D∈{L,R},

means: in state qqq, reading aaa, write bbb, move left or right, and enter q′q'q′.

Alternative conventions allow several tapes, a stationary move, or multiple halting states. Such variants can simulate one another. Exact state counts, however, depend on the convention.

A configuration records the tape, head position, and control state. A finite rule table determines a sequence

C0⟶C1⟶C2⟶⋯ .C_0\longrightarrow C_1\longrightarrow C_2\longrightarrow\cdots.C0​⟶C1​⟶C2​⟶⋯.

Some sequences reach a halting state. Others continue indefinitely.

Programs as inputs

A finite rule table can itself be encoded as a finite string or natural number. Let ⌜M⌝\ulcorner M\urcorner┌M┐ denote a description of a machine.

A universal machine takes such a description and an input xxx, then simulates MMM on xxx. If the simulated machine halts, the universal machine returns the corresponding result. If it runs forever, the simulation continues.

One fixed machine can thus perform different tasks by reading different descriptions. A program has become data that another program can copy, inspect, or execute.

Turing's universal machine was a logical construction. It was not an engineering blueprint for a later electronic computer, though it isolated a central idea of general-purpose computation.

A decision procedure that defeats itself

Turing's original paper used questions about machines producing an unlimited sequence of output symbols. The modern halting problem gives a closely related, particularly direct diagonal argument.

Suppose a machine HHH always terminates and correctly decides

H(⌜P⌝,x)={1,P(x) eventually halts,0,P(x) runs forever.H(\ulcorner P\urcorner,x)= \begin{cases} 1,&P(x)\text{ eventually halts},\\ 0,&P(x)\text{ runs forever}. \end{cases}H(┌P┐,x)={1,0,​P(x) eventually halts,P(x) runs forever.​

Construct a program DDD that does the opposite of the answer for a program applied to itself:

D(p)={loop forever,H(p,p)=1,halt,H(p,p)=0.D(p)= \begin{cases} \text{loop forever},&H(p,p)=1,\\ \text{halt},&H(p,p)=0. \end{cases}D(p)={loop forever,halt,​H(p,p)=1,H(p,p)=0.​

Now run DDD on its own description ⌜D⌝\ulcorner D\urcorner┌D┐.

If HHH predicts halting, DDD loops. If HHH predicts nonhalting, DDD halts. Either answer is wrong.

Undecidability of halting. No algorithm always terminates and correctly decides whether an arbitrary program halts on an arbitrary input.

Many individual programs can still be analyzed. A completed run proves halting. An invariant or repeating configuration may prove nonhalting. The theorem excludes a single total procedure that settles every case.

Back to first-order logic

Machine computations can be described using formulas. Suitable encodings reduce an undecidable machine problem to first-order validity. A universal validity decider would consequently decide that machine problem.

Church and Turing's 1936 results rule this out. First-order validities are computably enumerable, since proofs can be enumerated, but they are not decidable in general.

Propositional logic and some restricted first-order fragments remain decidable. Expressive scope matters.

Gödel and Turing therefore establish related boundaries through different statements. Incompleteness concerns what a fixed effective theory can prove. Undecidability concerns what any algorithm can decide uniformly. Coding connects them without making them interchangeable.

Busy Beaver

In 1962, Tibor Radó placed a form of noncomputability inside a sequence of finite integers.

Fix nnn ordinary states, two tape symbols, a blank tape, and a separate halting state. There are only finitely many rule tables. Among the machines that halt, their running times have a maximum.

Define

BB(n)=max⁡{steps⁡(M):M has n states and halts on the blank tape}.BB(n)= \max\{\operatorname{steps}(M): M\text{ has }n\text{ states and halts on the blank tape}\}.BB(n)=max{steps(M):M has n states and halts on the blank tape}.

This is the running-time version, also written S(n)S(n)S(n). Radó's productivity function Σ(n)\Sigma(n)Σ(n) instead maximizes the number of ones left on the tape. The two functions should not be confused.

Counting the candidates

There are 2n2n2n state-symbol pairs. A nonhalting instruction chooses one of two written symbols, one of two directions, and one of nnn next states: 4n4n4n possibilities.

For running time, the write and move made on a halting transition can be normalized to one halting action. Under this convention the table count is

The distinction matters at every state count. A remarkable candidate proves a lower bound. An exact answer must also settle the machines that have not stopped.

Why the maxima cannot be computed

Suppose an algorithm computed BB(n)BB(n)BB(n) for every nnn. To decide whether a particular nnn-state machine halts on blank input, run it for BB(n)BB(n)BB(n) transitions.

If it has not halted by then, it never will. Otherwise its halting run would exceed the defining maximum.

Any finite program and input can be compiled into a machine that starts on a blank tape. A computable Busy Beaver function would therefore solve the general halting problem. Hence BBBBBB is not computable.

Faster than every total computable function

The growth result is stronger:

for every total computable f,∃N ∀n>N,BB(n)>f(n).\text{for every total computable }f,\quad \exists N\ \forall n>N,\quad BB(n)>f(n).for every total computable f,∃N ∀n>N,BB(n)>f(n).

Here is the construction behind it. A fixed control program computes fff from an input numeral. An additional chain of states can write a numeral encoding the total state count, accounting for a fixed control overhead.

For each sufficiently large nnn, the resulting nnn-state machine computes f(n)f(n)f(n), then performs more than f(n)f(n)f(n) transitions before halting. Unused states can be added if needed. A fully specified compilation makes the fixed overhead precise.

Since this machine is among the candidates,

BB(n)≥steps⁡(Mn)>f(n).BB(n)\geq\operatorname{steps}(M_n)>f(n).BB(n)≥steps(Mn​)>f(n).

Exponentials, factorials, and the Ackermann function are all computable. Busy Beaver eventually exceeds each. Every particular BB(n)BB(n)BB(n) is still a finite integer. The obstacle concerns a uniform method for obtaining the sequence.

Compiling a conjecture into a machine

A program can test successive even integers for a counterexample to Goldbach's conjecture, halting exactly when it finds one. Similar encodings use computably checkable formulations of other mathematical statements.

In 2016, Adam Yedidia and Scott Aaronson gave explicit two-symbol machines with 4,888 states for Goldbach and 5,372 states for the Riemann hypothesis, halting exactly when the corresponding conjecture has a counterexample.

Knowing the exact relevant Busy Beaver value would provide a finite stopping deadline for these searches. Failure to halt by that deadline would establish that the machine never halts.

Those state counts belong to particular encodings, not an intrinsic scale of mathematical difficulty. The construction is a logical connection, not a practical strategy for resolving the conjectures.

The same paper describes a 7,910-state machine whose nonhalting cannot be proved in ZFC if ZFC is consistent. Its construction uses a specific combinatorial statement. It should be distinguished from the simpler conceptual machine that merely searches ZFC proofs for a contradiction.

When nonhalting expresses consistency

For that simpler search machine,

the machine never halts⟷Con⁡(ZFC).\text{the machine never halts} \quad\longleftrightarrow\quad \operatorname{Con}(\mathrm{ZFC}).the machine never halts⟷Con(ZFC).

With a faithful formalization, the second incompleteness theorem prevents consistent ZFC from proving its nonhalting.

An assertion of nonhalting can therefore be a concrete arithmetical statement that a specified theory cannot establish. Stronger assumptions are needed when making further claims about soundness or the actual behavior of a particular published machine.

A boundary made explicit

Hilbert asked for control over formal reasoning. Gödel encoded proofs in arithmetic. Turing encoded mechanical calculation in finite rule tables. Radó then expressed a computational boundary as a sequence of definite finite maxima.

The formalization made exact limitations visible. It also made new questions possible.

One such question returns us to set theory: when a familiar conjecture is independent of the axioms, can we construct models realizing the different answers? Cohen's forcing method will turn that question into a systematic practice.
